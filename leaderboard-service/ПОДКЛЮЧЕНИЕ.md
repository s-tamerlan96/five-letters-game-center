# Общая таблица «Цепочка на время»

Подготовлен сервер `/api/leaderboard`. Игрок вводит только ник. Ник, счёт, случайные идентификаторы устройства/захода и время записи хранятся в публичном GitHub; email, IP и другие поля сервер не сохраняет. Нельзя писать секретный ключ в HTML или `leaderboard.json`.

Уже подготовлено:

- Сервер: https://five-letters-leaderboard.vercel.app/api/leaderboard . Проверен публичный ответ `configured: false` и разрешение запросов от Pages.
- Проект Vercel: https://vercel.com/stamerlan96-3175/five-letters-leaderboard . Статус развёртывания READY.
- Ветка GitHub `leaderboards`; запись идёт в `results/YYYY-MM-DD.json`, не в опубликованную игру.
- URL сервера уже прописан в `roadmap/leaderboard.json`. Игра проверяет доступность записи при открытии.

Осталось подключить:

1. В GitHub создать **Fine-grained personal access token** только для `s-tamerlan96/five-letters-game-center`, Repository permissions → **Contents: Read and write**. Срок — минимальный подходящий для демо. Не отправлять токен в чат.
2. В [настройках Vercel](https://vercel.com/stamerlan96-3175/five-letters-leaderboard/settings/environment-variables) добавить секретную переменную **GITHUB_LEADERBOARD_TOKEN** для Production. Затем сделать Redeploy последнего развёртывания.
3. Обновить игру, пройти заход на двух устройствах и отправить два разных ника. Оба результата должны появиться в таблице и файле GitHub; повторное нажатие не должно создавать дубликат.

Пока ключа нет, игра запоминает ник и результат на устройстве и пишет, что общая таблица не подключена. После добавления ключа игрок обновляет игру и нажимает «Отправить результат».

Сутки таблицы — Москва. Один результат с устройства в день, до 24 слов. При равном счёте выше тот, кто раньше записал результат. Показываются первые 10 и собственная строка, если игрок ниже. По итогам дня: 1 место — 3 сундука, 2–3 — 2, 4–10 — 1. Награда выдаётся только после получения общей закрытой таблицы, минимум за одно слово. Демо сдвига дня не отправляется в общую таблицу.

Ограничения прототипа: результат не защищён от подделки игрового клиента; идентификатор устройства можно сбросить. Перед реальным соревнованием нужен серверный заход, проверка ответов и защита от частых запросов. Сервер ограничивает размер запроса, формат ника, даты и счёт, использует фиксированный путь репозитория и повторяет запись при конфликте GitHub SHA.

Проверено локально: валидация, повторная запись, одновременная запись двух игроков, сортировка. Живая запись требует ключа и отдельной проверки после подключения.
